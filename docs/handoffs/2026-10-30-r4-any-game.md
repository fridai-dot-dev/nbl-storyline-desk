# Build brief: R4, run the desk on any finished game

**Approved by Bart:** 2026-10-29 (scope) and 2026-10-30 (priority) · **Builder:** Codex via `/codex-build` (Terra builds, Sol reviews), Claude orchestrates · **Branch:** create `r4-any-game` from `main`.

Everything you need is in this brief. The earlier design document has been removed from the repo, so the decisions it held for this round are restated here. If something isn't covered, ask Bart rather than guessing.

## Goal

Anyone can run the NBL Storyline Desk on a finished NBL27 game of their choosing with one command. It collects that game's material the way the demo did, runs the pre-game and post-game desks, and builds a browsable site. It shows what it will fetch and spend first, and never gives agents the web or a shell.

Today only the stats side works for any game. `storydesk fetch --game <id>` takes any match UUID, but the commentary, live chat, press conferences and articles for the Round 1 demo game were collected by hand. That gap is this round.

## Decided (by Bart, in the design conversation)

**1. Code collects and agents only analyse.** The collector is plain code (yt-dlp plus HTTP). The agents keep their current locked-down tool set: only the desk's own MCP query tools, with WebSearch, WebFetch, Bash, Write and Edit disallowed, `setting_sources=[]`, `strict_mcp_config=True`, and budget caps. Don't add web tools to any agent.

**2. `storydesk collect --game <id>`** builds `data/corpus/` for that game:
- **Broadcast:**
  - Find the NBL YouTube live stream for the game: search the NBL channel's streams by both team names and the game date. `--stream-url` overrides.
  - Download its auto-captions into commentary (`transcripts.jsonl`, ~30-second chunks, the same schema as today).
  - Download its live-chat replay into `fans.jsonl`. Drop author names at collection; never store them.
- **Press conferences:**
  - Look on the NBL channel and both clubs' channels for videos published within a few hours after the game.
  - Use their YouTube captions, not Whisper. Whisper stays optional and off by default.
  - `--presser-url` (repeatable) and `--skip-pressers` override.
- **Video comments:** for each team's last ~5 games, collect comments on the highlights and press-conference videos. Each comment's time is its `available_at`, so they reach the *next pre-game* brief and never the post-game run.
- **Articles:**
  - Take NBL.com articles from the sitemap that mention either team in the prior 4 weeks (robots.txt permits this).
  - Use each article's own `datePublished`, which is day-level only.
- **Fallback:** if a source can't be found, record that and carry on. The run then states "nothing found" for that source.

**3. The availability rule.** Every corpus item carries `available_at`:
- Live items use the time they were spoken or sent. Broadcast captions assume LK would transcribe its own feed live in production; say so in the docs.
- Press conferences use the upload time.
- Comments use the comment time.
- Articles are day-level, and same-day counts as *after* the cutoff.

Tools filter on `available_at ≤ cutoff`. The existing corpus uses `timestamp` (transcripts, fans) and `date` (media), so migrate it without changing the demo game's published results.

**4. `storydesk demo --game <id> [--dry-run] [--runs pre_game,post_game]`:**
- **The full pipeline:** stats fetch → build-db → collect → runs → site, written to `out/<game_id>/`. Then it prints the page to open.
- **Default runs:** pre-game and post-game.
  - `--runs` can add `supplemental`, which runs only if press conferences were found.
  - It can also add `follow_up`, which needs `--question`.
- **Login:** works with a Claude login or `ANTHROPIC_API_KEY`.
- **`--dry-run`:** makes no model calls. It prints the sources found (with counts), each run's cutoff, the models, the spend caps and an estimated cost range.

**5. `storydesk verify`** runs the offline checks and prints one line, for example "N checks passed · no model calls · no network".

**6. The security note** (`docs/before-you-run.md`) gains the command sections:
- **Domains:** every domain the collector contacts, verified against the code. yt-dlp traffic is listed honestly as "via yt-dlp (YouTube's domains)", not as a closed list.
- **How to run safely:** dry-run first, use a separate Console API key with a spend limit, and run it in a container or fresh VM if you prefer.
- **Line references:** keep its existing file:line references correct (a check verifies them).

**7. Dependencies:** pin them with a lockfile. `yt-dlp` is a declared dependency.

**8. Docs after it works:**
- Update the README "Run it" section, which today says plainly that the desk can't be pointed at another game.
- Update `docs/data-provenance.md`: its timing table and social note already say video comments aren't collected yet.
- Change only what's now true.

## Facts — don't re-derive

**The demo game:**
- NBL27 Round 1, Melbourne United 95–97 Adelaide 36ers, 19 September 2026, match UUID `36dbeb55-58ad-11f1-a69b-43a6b5595d3e`.
- Cutoffs:
  - pre-game: 06:30 UTC (tip-off minus 3 hours)
  - post-game: the final whistle, 11:26:37 UTC (the final period's `period / End` event in the play-by-play)
  - supplemental: 12:50 UTC, after both press-conference uploads
- Press conferences were published 12:23:56 (Adelaide, NBL channel, `1id823Gz8jg`) and 12:44:33 UTC (Melbourne United's own channel, `v6dQVTM8zWs`).
- The broadcast stream is `jfZn7syBTUI`, starting 09:28:34 UTC. Its live chat has 2,274 messages, many in Tagalog, with plenty of betting talk.

**Stats:**
- `storydesk fetch` pulls the `nblr_data` GitHub releases (results, box_team, and `pbp.csv`, which actually holds player box scores) plus the NBL match API (`prod.rosetta.nbl.com.au/get/match/<uuid>/live/all`). That API serves the league's Genius Sports / FIBA LiveStats feed and covers NBL27 games.
- The match file is saved as `match_opener.json`. Check that `build-db` and `prepare` work for any game id, not just the opener.
- **Never parse `pbp.rds`.** It crashed WSL before.

**Corpus schemas today** (keep them, adding `available_at`):
- `transcripts.jsonl`: `{id, source_type: "commentary", source_title, source_url, timestamp, quote}`
- `fans.jsonl`: `{id, source_type: "fans", text, score, timestamp, source_url}`
- `media.jsonl`: `{id, source_type: "media", title, date, url, excerpt}`
- There are synthetic test fixtures in `tests/fixtures/corpus/`.

**Social:**
- Reddit API access needs Reddit's approval, which is unlikely to come in time.
- X reads are pay-per-use. Neither is in scope.

**Cost:** a pre-game plus post-game live run costs about US$3.50 at API prices.

**Environment:**
- WSL has about 7.7 GB of RAM. Cap memory before any heavy job.
- The full test suite takes about 18 minutes, so iterate on targeted test files and run the full suite once at the end.
- Live runs share Bart's Claude window. Start them at the top of a fresh window, and treat a "session limit" result as a failed run.

## How to work

- Read `lessons.md` first, especially lessons 8, 9, 11 and 12.
- **Never satisfy a check with hidden or invisible content** (`display:none`, `aria-hidden` compatibility nodes and the like). If an old check contradicts a new decision, stop and ask. This happened in R1, and the cleanup is still pending.
- Codex never edits the checks. A disagreement goes back as `NEEDS_DECISION`.
- No live model calls in tests.
- **The stretch goal, proof on a real second game:** from a clean clone, follow only the README and run `demo` on another finished NBL27 game. It costs about US$3.50. Do it only with Bart's go-ahead. Bart decides afterwards whether that game replaces the opener as the showcase.
- **Pushing to `main` deploys the public GitHub Pages site,** so ask Bart before every push. Never commit notes about people.
