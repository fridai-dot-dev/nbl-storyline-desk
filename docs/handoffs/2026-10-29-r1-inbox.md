# Build brief: R1, inbox and trust

**Design approved by Bart:** 2026-10-29 · **Builder:** Codex (gpt-5.6-terra) · **Integrator:** Claude Code session on branch `gm-handover`. Everything you need from the design conversation is in this brief. If something isn't, ask with `NEEDS_DECISION` rather than searching for it or guessing.

## Goal

The site opens on an inbox: the pre-game and post-game emails as they'd land with LK's internal teams, with the board moved to `board.html`. Every story carries a plain headline, a premise, stance and comment links, and the Agora look. The stance model replaces per-audience sign-off wording. A `copy-pass` command fills the new copy fields without touching the judge's output. A docs-only security note and a "what's rough" page exist.

## Facts — don't re-derive

- **Agora values** come from agora.fridai.dev's live CSS. They're the §4D values, so use them exactly.
- **Bart's visual preferences:**
  - Emails and the inbox chrome are **always white**. Only the page around them goes charcoal.
  - No grey text on dark backgrounds.
  - Story and chart boxes need **clearly visible borders** (the v4 mockup uses solid `#cfcfcf` borders on a `#f3f3f3` box fill inside the email).
  - The test line must stand out: solid black, 2px, labelled "test line: N".
  - Sensitive tags are orange.
- **Copy rules from Bart:**
  - Each story opens with a plain question headline and a 1–2 sentence premise a non-basketball reader understands. "Goulding's 'easier looks'" with no context failed his read.
  - Never write "we" without a subject. The section is "The desk's top pick", and it says why it ranks first and that it's a suggestion.
  - Steering and follow-ups are framed as open: "ask for anything", "for example", "reply with a number, change one, or ask your own".
- **Stance semantics** (Bart's decisions):
  - Stances are `push`, `use_if_raised` and `steer_away`, each with an optional comment, and anyone can set one.
  - There's one live stance per role.
  - Any live `steer_away` blocks promotion.
  - Override roles ("League GM", "LK director") clear a block immediately, and the record says "Cleared by <role> over <role>'s steer away".
  - Only an override role lifts an override role's steer away.
  - All recipients are internal. The old "cleared for producers but not partners" framing was rejected as misreading how a league's comms work.
- **Hallucination risk is real.** Drafting the mockup, Claude added "the league's leading scorer" and a calf-to-minutes causal link, neither of which is in the findings. That's why the copy pass may only restate stored text. Its prompt must say so, and check 12 enforces it.
- **The copy pass must leave the judge's scores, top pick and follow-ups byte-identical**, so the README's "What it found" stays true.
- **No live model calls in this build.** Claude runs `copy-pass --live` on the four published runs later, at the top of a fresh Pro window. Build and test with the SDK mocked, as the existing tests do.
- **The opener's runs aren't re-run.** Its pre-game has no fan-comment data, so the fan section is omitted there, with the sentence check 57c expects.
- **The simulated round** (`published/simulated-round.json`) has `feedback` items with an `action` (for example `back`) and `directives`. Map `back` → `push` and `drop` → `steer_away`; you map the rest. Every simulated item stays labelled "simulated".
- **`leadership-view.html` is superseded** by `inbox.html`. The board (`producer-board-v2.html`) and finding (`finding-detail.html`) mockup structures stay as they are; restyle only.
- **The security note's facts:**
  - The lead agent's options are in `src/storydesk/agents.py` around lines 117–131: allowed tools are `Agent` plus the desk's MCP tools; disallowed are WebSearch, WebFetch, Bash, Write and Edit; `permission_mode="dontAsk"`; `max_budget_usd=5.0`; `setting_sources=[]`; `strict_mcp_config=True`.
  - The judge is in `src/storydesk/runner.py` around lines 163–165: no tools, `max_turns=1`, `max_budget_usd=1.0`.
  - The post-game deadline is 25 minutes, inside a 30-minute hard cap.
  - Re-check the line numbers after your edits: check 31 verifies them.
- **WSL has about 7.7 GB of RAM.** Never parse `pbp.rds`.
