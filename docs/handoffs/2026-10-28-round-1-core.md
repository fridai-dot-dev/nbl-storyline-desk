# Build brief: NBL Storyline Desk, round 1 (the Must list)

**Design approved by Bart:** 2026-10-28 · **Builder:** Codex (gpt-5.6-terra) · **Integrator:** Claude Code (Opus 5.5). Everything you need from the design conversation is in this brief. If something isn't, ask with `NEEDS_DECISION` rather than searching for it or guessing.

## Goal

Build a Python package, `storydesk`, in `src/storydesk/`, plus the prompt files in `prompts/`. Together they implement the engine in the design, and the non-live test suite passes when they're done. The engine has these parts:
- a stats database with `as_of` views
- the store
- the agent tools and a stdio MCP server
- the gates and the charts
- the Agent SDK configuration for four run types (an Opus lead and four Sonnet specialists)
- the runner (ledger, deadline, `--live` guard)
- the starting-set digest builder
- the static site
- the scorecard

**Live runs are not part of this build.** Claude runs them afterwards on Bart's Claude login. Do implement the live path, `runner.run_live`, carefully against the installed SDK.

## Design

`docs/superpowers/specs/2026-10-28-nbl-storyline-desk-design.md`. The sections that matter most are 4 (constraints), 5 (the design), 8 (checks) and 9 (Must). ### `storydesk.data`
- `build_stats_db(db_path, *, results_csv, box_team_csv, box_player_csv, match_json_paths)` builds a DuckDB file.
- SQL sees four relations through `as_of` views: `results`, `box_team`, `box_player` and `pbp`.
- Keep the CSV column names as they are, for example `box_team.name`, `home_away`, `p1_score`–`p4_score`, `ot_score`, `score`, `season`, `results.match_time_utc`, `home_team_name` and `away_team_name`. Make integer columns integers, with `NA` as NULL. Let DuckDB read the CSVs.
- `pbp` columns: `match_id, action_id, period, period_type, clock, score_home, score_away, action_type, sub_type, team, player, timestamp`.
  - Source: `data[0].play_by_play` in each match payload.
  - `score_1` is the home score and `score_2` the away score (verified).
  - Map `team` and `player` to names where the payload allows, otherwise NULL.
- **Visibility.** A match is visible at `as_of` when its end time is at or before `as_of`, compared at whole-second precision.
  - End time is the timestamp of the `system_action_type == 'game_game_completed'` event, truncated to the second, when the match has a payload.
  - Otherwise it's `results.match_time_utc` plus 3 hours.
  - Payload timestamps and `match_time_utc` are UTC with no offset.
  - All four relations show only rows from visible matches.

### `storydesk.store.Store(path)`
- `.path`, `.init()`
- `.start_run(run_type, game_id, as_of, route) -> int`
- `.get_run(id) -> dict`, with keys including `id, run_type, game_id, as_of, route, status, cost_usd, duration_s, model_usage` (a dict), `num_agents, started_at, finished_at`.
- `.findings(run_id, include_dropped=False) -> list[dict]` and `.get_finding(id) -> dict`, with keys including `id, run_id, parent_id, agent, source_type, claim, kind, number, query, chart` (a dict or None), `status, sensitivity, audience` (a list), `prompted_by, drop_reason`.
- `.evidence(finding_id) -> list[dict]`, with keys `source_type, url, ref, quote, stance`.
- `.add_signoff(finding_id, approver, audience)`, `.add_feedback(finding_id, role, action, text=None, simulated=True)`
- `.add_directive(owner_role, text, mandatory=False, expires=None) -> int`
- `.add_request(anchor_finding_id, asked_by, question) -> int`, `.answer_request(request_id, run_id)`, `.requests() -> list[dict]`
- `.log_tool_call(run_id, agent_id, agent_type, tool, args_json)`
- **SQLite tables** (the live tests read these columns by name):
  - `runs(id, run_type, game_id, as_of, route, status, cost_usd, duration_s, model_usage, num_agents, …)`
  - `findings(id, run_id, parent_id, kind, status, …)`
  - `evidence`, `directives`, `signoffs`
  - `requests(id, anchor_finding_id, asked_by, question, answered_run_id)`
  - `feedback(…, simulated)`
  - `tool_calls(run_id, agent_id, agent_type, tool, …)`
  - Agent tracking tables are named `track_<name>`.
- **Status flow:** `pending` becomes `shipped`, `dropped` or `held`.

### `storydesk.tools`
- `ToolContext(stats_db, store, corpus_dir, run_id, as_of)`, where `as_of` is an ISO string or a datetime, plus `ToolError`.
- **The nine tool functions take no `as_of` parameter.** The cutoff comes from the context or the server environment, so an agent can't widen it.
- `stats_sql(ctx, sql, limit=200) -> {"columns", "rows", "truncated"}`
  - Read-only: open the database read-only with `enable_external_access=false`.
  - Accept exactly one SELECT or WITH statement. Reject writes, DDL, ATTACH, COPY and file-reading functions.
  - Values must be JSON-serialisable, with timestamps as ISO strings.
- `get_game(ctx, match_id)` returns `match_id, home_team, away_team, start_time` and `status`.
  - `status` is `"scheduled"` if the match isn't visible yet, otherwise `"complete"`.
  - When complete it adds `home_score, away_score` and `quarters={"home":[…],"away":[…]}`.
- `search_transcripts`, `search_fans` and `search_media`, each taking `(ctx, query, limit=…)`.
  - Search is case-insensitive and keyword-based: an item matches if any query token of 3 or more characters appears in it.
  - Corpus files are `corpus_dir/{transcripts,fans,media}.jsonl`, in the format of `tests/fixtures/corpus`.
  - Cutoffs: transcripts and fans by timestamp, at or before `as_of`. Media works at day level: include an item only if its `date` is strictly earlier than the UTC date of `as_of`.
  - `search_fans` never returns `author` or handle fields, and strips `u/…` and `@…` handles from text.
- `write_finding(ctx, *, agent, source_type, claim, kind, evidence, number=None, query=None, chart=None, parent_id=None, audience=(), sensitivity=None, prompted_by=None) -> int`
  - Kinds: `checked`, `attributed`, `qualitative`, `nothing_found`.
  - Validation follows `tests/test_tools.py`.
  - `chart` is `{"type": "bar"|"line", "query": str, "y_label": str}`. Its query returns the columns `label, value, highlight`.
- `read_findings(ctx, *, agent=None)`
- `create_tracking_table(ctx, name, columns)` and `update_tracking_table(ctx, name, rows)`.
  - Names must match `^[a-z][a-z0-9_]{0,40}$`, and column types must be TEXT, INTEGER or REAL.
  - The tables live in the store database as `track_<name>`.

### `storydesk.mcp_server`
- A stdio MCP server named `desk` that exposes exactly those nine tools. Use the API of the installed `mcp` 2.3.0, and inspect `.venv` to check it.
- It builds its context from `STORYDESK_RUN_ID`, `STORYDESK_AS_OF`, `STORYDESK_STATS_DB`, `STORYDESK_STORE` and `STORYDESK_CORPUS`.
- `python -m storydesk.mcp_server --list-tools` prints a JSON list of the tool names and exits 0.
- The server logs every call with `log_tool_call`, with a null `agent_id`, because only the SDK hook knows which agent made the call.

### `storydesk.gates`
- `SENSITIVE_CATEGORIES` contains `conflict, injury, officiating, legal, fan_quote`.
- `recheck_finding(stats_db, as_of, finding) -> bool`.
  - Run the finding's query through the `as_of` views and compare the first column of the first row with its number, within 1e-6.
  - Bools compare as 0 or 1. No rows means False.
- `apply_gates(store, run_id, *, stats_db, as_of) -> dict` returns at least `recheck_pass_rate` (over shipped checked findings, 1.0 if there are none), `shipped`, `dropped` and `held`. It applies these rules in order:
  1. A checked finding that fails recheck is dropped, with a reason.
  2. A finding that breaks the data boundary is dropped.
  3. A finding with a sensitivity category is held.
  4. Anything else ships.

  If a chart query's highlighted value doesn't equal the finding's number, the chart is removed but the finding still ships.
- `coverage(store, run_id, required) -> {source_type: count | "nothing found" | 0}`
- `visible_findings(store, run_id, audience)`, with audiences `internal`, `producers` and `partners`.
  - `internal` sees shipped and held findings, each with its status.
  - The other audiences see shipped findings, plus held ones that have a sign-off for that audience.
- `needs_boundary(claim)` and `boundary_ok(claim)`.
  - A claim needs a boundary when it has a record word (most, fewest, first, last, record, highest, lowest, best, worst or longest) and also says "since 2015-16", "2015/16", "2015–16" or "2015", the start of the box-score and play-by-play data.
  - `boundary_ok` is true when the claim doesn't need a boundary, or when it contains "since at least".

### `storydesk.charts`
- `render_bar_chart(title, labels, values, highlight_index, y_label=None) -> str`, `render_line_chart(…) -> str`, and `check_chart(svg, expected_title) -> list[str]`, which returns the list of problems.
- **SVG conventions:**
  - The root is `<svg xmlns=… data-baseline="<y of the zero line>" aria-label=…>`, and its first child is a `<title>` holding the claim.
  - Each mark (a `rect` for bars, a `circle` for points) has `data-label` and `data-value`, and exactly one mark has class `highlight`.
  - Every category has a visible `<text>` label.
  - For every bar, `y + height` equals `data-baseline`.
- Style it like the mockups: one accent hue, muted marks that aren't highlighted, recessive axes. Inline only, with no external JS or CSS.

### `storydesk.agents`
- **`RUN_TYPES`**, keyed by `pre_game, post_game, supplemental, follow_up, smoke`, each with `time_limit_s` and `required_sources`:
  - `post_game`: 1500 seconds; `required_sources` must include stats, commentary and fans. The other limits are your call; the design suggests about 1800 for pre-game, 900 for supplemental and 600 for follow-up.
- **`build_options(run_type, *, run_id, as_of, stats_db, store_path, corpus_dir, digest_dir, question=None, anchor_finding_id=None) -> ClaudeAgentOptions`:**
  - `model="claude-opus-5-5"`.
  - `system_prompt` is `prompts/lead.md`, then `prompts/runs/<run_type>.md`, then a line stating the budget and time limit.
  - `agents` holds the four specialists (stats, commentary, media, fans). Each is an `AgentDefinition` with:
    - `description`
    - `prompt` containing `prompts/<name>.md`
    - an explicit `tools=["mcp__desk__<tool>", …]`
    - `mcpServers=["desk"]`
    - `model="claude-sonnet-5-5"`
    - `maxTurns`
    - `effort`
  - `mcp_servers={"desk": {"type": "stdio", "command": sys.executable, "args": ["-m", "storydesk.mcp_server"], "env": {…STORYDESK_*…}}}`
  - `allowed_tools` includes `Agent` and the desk tools.
  - `disallowed_tools` includes at least WebSearch, WebFetch, Bash, Write and Edit.
  - `env={"CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH": "1", "CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS": "5", "CLAUDE_CODE_DISABLE_AUTO_MEMORY": "1"}`
  - `max_budget_usd=5.0`, `setting_sources=[]`, `strict_mcp_config=True`.
  - `hooks` has `PostToolUse` and `SubagentStop` matchers whose callbacks write `agent_id`, `agent_type` and the tool to `Store.log_tool_call`.
  - Pick a headless permission setup in which file-writing tools stay unavailable.
- **`build_prompt(run_type, *, digest_dir, question=None, anchor_finding_id=None) -> str`** is the lead's user prompt. It contains the digest and the run brief, and for a follow-up the question and the anchor ID.
- **`build_cli_config(run_type, **same kwargs) -> (agents_json, {"mcpServers": {"desk": …}})`** produces the configuration for `claude -p --agents … --mcp-config …`, with the same prompts and models.

### `storydesk.runner`
- `record_result(store, run_id, result, *, route, num_agents)` writes the ledger:
  - status `complete` on success, otherwise `error` or `timeout`
  - `cost_usd` from `total_cost_usd`
  - `duration_s` as `duration_ms` / 1000
  - `model_usage` and `num_agents`
- `async enforce_deadline(awaitable, seconds, interrupt) -> (status, result)`. On timeout it awaits `interrupt()` and returns `("timeout", None)`.
- `run_live(...)` does the real run, in this order:
  1. prepare the digest
  2. build the options
  3. open a `ClaudeSDKClient` and run the query, collecting the `ResultMessage`
  4. enforce the deadline with `client.interrupt`
  5. apply the gates
  6. run the judge
  7. record the result

  It's for real runs only and isn't tested.

### `storydesk.prepare`
- `prepare_run(run_type, *, game_id, as_of, stats_db, store, corpus_dir, out_dir) -> Path` writes compact markdown digests into `out_dir`. Suggested files:
  - `game.md`
  - `form.md`, recent results and box scores for both teams
  - `history.md`, head-to-head and quarter records
  - `commentary.md`, `fans.md`, `media.md`
  - `directives.md`
- Everything goes through the `as_of` views and tools, and nothing after `as_of` ever appears.
- Pre-game includes the teams, venue and tip-off, but not the result.
- Aim for under about 4,000 words in total, because every specialist reads it.

### `storydesk.judge`
- `novelty_similarity(claim, coverage_texts) -> float in [0, 1]`: deterministic, for example the maximum Jaccard similarity over lowercase word tokens.
- `score_findings(store, run_id, coverage_texts, scorer=None)` stores the novelty, audience-fit and direction scores. The default scorer is one Claude call using `prompts/judge.md` with no tools, live only.

### `storydesk.site`
`build_site(store, stats_db, out_dir, *, game_id) -> list[Path]` produces self-contained static HTML: inline CSS, no CDN, relative links that all resolve, and light and dark themes.
- **`index.html`** is the golden path: what this is, links to each page, how it works and the cost per run.
- **`pre-game.html`**.
- **`outbox/post-game-email.html`** is the email-first leadership briefing. It contains:
  - what happened
  - what moved since pre-game
  - the in-game pulse
  - angles with static Back it, Comment, Make it a directive and Drop buttons
  - held items shown as held
  - directives
  - "Briefing ready N min after full time"
  - the cost as `$X.XX`
  - simulated feedback labelled "simulated"
- **`findings/<id>.html`**, one for every finding that `internal` can see (shipped or held) across all of the game's runs. Each page shows:
  - the claim, its status and audience tags
  - the chart, built from the chart spec through the views at the run's `as_of`, and only when the highlighted value equals the number
  - "How we know", with the recheck stamp and the query inside a collapsed `<details>`
  - the trail: links to the parent and children
  - evidence with quotes and source links, never fan handles
  - follow-up requests anchored on this finding, with their answers
- Dropped findings get no page. Test fixtures and the synthetic corpus never reach the published site.

### `storydesk.scorecard` and the CLI
- `python -m storydesk scorecard --store --stats-db --run-id --json` prints JSON with `recheck_pass_rate, coverage, novelty, audience_fit, direction, held, duration_s, cost_usd`. A score that hasn't been computed is null.
- **`storydesk.cli`** is also reachable as `python -m storydesk` through `__main__.py`. Subcommands:
  - `fetch`: downloads the nblR CSVs and the chosen game's match JSON to `data/raw/`; the URLs and headers are in the facts below
  - `build-db`
  - `run <run_type> --game <uuid> [--as-of …] [--question … --anchor …] --live`; without `--live` it exits non-zero and prints a message containing `--live`
  - `scorecard`
  - `site`

## Prompt requirements (`prompts/*.md`)

Write them for capable models: plain and direct, with no shouting and no all-caps rules. Each file must be over 200 characters, and the tests check that each one exists and is included.

- **`lead.md`** describes the editor-in-chief of a storyline desk for NBL media, and covers:
  - the job comes from the run brief
  - the digest is a floor, not a fence
  - delegate to specialists through the Agent tool, in parallel
  - choose which proposed lines to follow, within the budget and the time limit, and state both
  - merge and de-duplicate findings, and link them into chains with `parent_id`
  - tag audiences: leadership, producers, social, broadcast, partners
  - link each finding to a directive with `prompted_by`, or mark it unprompted and keep unprompted finds a minority
  - avoid the three ways a run disappoints: obvious, too niche, off-direction
  - finish with a short summary
- **Specialists:** `stats.md`, `commentary.md`, `media.md`, `fans.md`. Each covers:
  - its sources and tools
  - every finding goes through `write_finding`, never prose alone
  - the evidence rules
  - the kinds of finding: a checked finding's SQL must return the number in its first cell; attributed numbers live only inside quotes and are checked against the stats whenever possible
  - the data-boundary wording, "since at least 2015-16"
  - the sensitivity categories
  - write `nothing_found` when a source yields nothing
  - propose new lines in other sources back to the lead in the final reply, rather than straying
  - for stats: per-possession thinking, small-sample warnings and regression to the mean
- **Run briefs** in `runs/`:
  - `pre_game.md`: storylines to watch, milestones within reach, and what would confirm or contradict each. It serves producers and the live social and stats team, and includes a steer for leadership.
  - `post_game.md`: what happened, what moved against pre-game, and whether to elevate, put in context, monitor, play down or challenge. It must finish within 25 minutes.
  - `supplemental.md`: what's new since the briefing, from the press conferences and fresh fan reaction.
  - `follow_up.md`: answer the user's question anchored on a finding, with every answer linked as a child of it.
- **`judge.md`:** a rubric for novelty against coverage published before the cutoff, for audience fit, and for the link to direction. Scores run from 0 to 1, and the output is JSON.

## Facts: don't re-derive

**Environment**
- Python 3.12 virtualenv in `.venv`, with `claude-agent-sdk` 0.2.174, `mcp` 2.3.0, `duckdb` 2.0.0, `jinja2` 3.1.6, `pytest` 9.2.0 and `pytest-asyncio`. Run tests with `.venv/bin/python -m pytest -q`. Network may be unavailable.
- The machine is WSL with about 7.7 GB of memory. Never load big files wholesale into Python objects; let DuckDB do it. A memory blow-up crashes WSL.

**The SDK, as installed (checked in-session)**
- `AgentDefinition` fields are camelCase: description, prompt, tools, disallowedTools, model, skills, memory, mcpServers, initialPrompt, maxTurns, background, effort, permissionMode.
- `ClaudeAgentOptions` fields are snake_case and include: tools, allowed_tools, system_prompt, mcp_servers, strict_mcp_config, permission_mode, max_turns, max_budget_usd, disallowed_tools, model, env, hooks, agents, setting_sources, effort, cwd.
- `ResultMessage` has subtype, duration_ms, is_error, num_turns, total_cost_usd, usage, result, model_usage and terminal_reason.
- `ClaudeSDKClient` has `query`, `receive_response` and `interrupt`. The hook matcher is `HookMatcher(matcher, hooks, timeout)`.
- Inside a sub-agent, PostToolUse hook input carries `agent_id` and `agent_type` (optional fields); SubagentStop carries them always.
- The SDK has no session deadline and no per-sub-agent deadline. Enforce the time limit in code, and cap specialists with `maxTurns`.
- Open Claude Code bug #30280: sub-agents don't reliably inherit MCP tools. Hence explicit `mcpServers` and `tools` on every specialist.

**Data**
- The match API is `https://prod.rosetta.nbl.com.au/get/match/<uuid>/live/all`, called with these headers: `accept: */*`, `origin: https://nbl.com.au`, `referer: https://nbl.com.au/`, and a browser user-agent.
  - It returns `{"data": [match]}` with `play_by_play` (916 events for the opener), `player_match_statistics`, `team_match_statistics`, `home_team`, `away_team` and `start_time`.
  - For the opener, the "game completed" event is at 2026-09-19T11:35:07.684.
- The nblR CSVs are at `https://github.com/JaseZiv/nblr_data/releases/download/<tag>/<file>`:
  - `match_results/results_wide.csv`
  - `box_team/box_team.csv`
  - `pbp/pbp.csv`, which is **mislabelled** and actually holds player box scores; use it as `box_player`
- **Never parse `pbp.rds`.** `pyreadr` can't read it, and the pure-Python reader exhausted WSL's memory.
- Results go back to 1979. Box-score and play-by-play data start in 2015-16, which is the data boundary.
